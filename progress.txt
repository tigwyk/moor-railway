## Codebase Patterns
- MCP host crate is at `crates/mcp-host/src/`; main source files: `moor_client.rs`, `mcp_server.rs`, `connection.rs`, `main.rs`
- `MoorClient` wraps ZMQ RPC calls to the mooR daemon; login uses `mk_login_command_msg` with connect_args vec where args[0] is the verb ("connect" or "create")
- `Obj` implements `Copy`, so don't use `.clone()` on it (clippy catches this)
- Login result from daemon includes: `success`, `auth_token`, `connect_type` (ConnectType enum), `player` (Obj), `player_flags` (u16) — defined in `moor_rpc.fbs`
- Reconnection always uses `LoginMode::Connect` regardless of original mode, since the player already exists after creation
- Clippy enforces collapsible `if let` chains — use `&&` syntax for nested `if let` guards
- `SessionManager` in `session_manager.rs` manages dynamic player sessions; `ConnectionManager` in `connection.rs` is the old static approach (will be replaced in US-004)
- `CreationPolicy` enum (Open/Token/AdminOnly/Disabled) lives in `session_manager.rs`; it implements `FromStr` for clap parsing and `Serialize`/`Deserialize` for figment YAML config
- `humantime` crate is available in mcp-host for parsing duration strings like "30m", "1h", "300s"
- CLI args use `String` types for enums/durations, parsed manually after figment extraction, to keep figment YAML compatibility simple
